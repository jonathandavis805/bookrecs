# UI Improvements - November 11, 2026

## Summary
Made two key UI improvements to enhance consistency and usability across the application.

## Changes

### 1. Book Detail Page Width Consistency
**File Modified:** `web/src/components/BookDetail.tsx`

**Problem:** The book detail page was not respecting the app's max-width constraint of 780px, causing it to appear wider than other pages.

**Solution:** Wrapped the entire BookDetail component content in a `<div className="app">` container, matching the structure used by Profile and other page components.

**Before:**
```tsx
return (
  <div className="page">
    {/* content */}
  </div>
);
```

**After:**
```tsx
return (
  <div className="app">
    <div className="page">
      {/* content */}
    </div>
  </div>
);
```

### 2. Clickable Book Titles on Profile Page
**File Modified:** `web/src/components/Profile.tsx`

**Problem:** Book titles on the profile page (friend profiles) were not clickable, unlike books on the main page. Users couldn't navigate to book details from a friend's profile.

**Solution:** Wrapped all book titles in anchor tags with the `book-title-link` class, linking to the book detail page using hash routing (`#/book/{book_id}`).

**Sections Updated:**
- Currently Reading section (line ~150)
- Books Read section (line ~185)
- Wishlist section (line ~220)

**Before:**
```tsx
<div className="title">{b.title}</div>
```

**After:**
```tsx
<div className="title">
  <a href={`#/book/${b.book_id}`} className="book-title-link">
    {b.title}
  </a>
</div>
```

## Technical Details

### CSS Classes Used
- `book-title-link`: Already defined in the existing stylesheet with hover effects
- `app`: Main container class with `max-width: 780px` for consistent page widths
- `page`: Inner container for page content

### Routing
Book detail pages use hash-based routing: `#/book/{bookId}`
- Example: `#/book/42` displays details for book with ID 42
- Handled by the App component's route parser
